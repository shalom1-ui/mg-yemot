# שליטה על MG S9 מטלפון כשר דרך קו ימות המשיח (מתארח על Render)

מדריך והקוד המלאים להקמת תפריט טלפוני (IVR) שמאפשר לך, מכל טלפון כולל טלפון
כשר, להתקשר לקו ימות המשיח הקיים שלך וללחוץ מספרים כדי להדליק/לכבות מזגן,
לנעול/לפתוח דלתות, לשמוע סטטוס רכב (סוללה, דלק, מיקום, נעילה) ולהפעיל
צפצוף/הבהוב אורות לאיתור הרכב.

## איך זה עובד (סקירה)

```
טלפון כשר ---חיוג---> קו ימות המשיח (השלוחה שתגדיר)
                              |
                              | קורא (HTTP) לשירות שלך ב-Render בכל לחיצת מקש
                              v
                 קונטיינר אחד ב-Render, עם שלושה תהליכים:
                 ┌─────────────────────────────────────┐
                 │  yemot_bridge.py (Flask)              │ <- מדבר עם ימות המשיח
                 │  mg-gateway (SAIC/MG iSMART gateway)  │ <- מדבר עם MG בענן
                 │  mosquitto (MQTT broker פנימי)        │ <- מחבר בין השניים
                 └─────────────────────────────────────┘
                              |
                              v
                       שרתי MG / SAIC בענן  --->  הרכב שלך
```

שלושת התהליכים רצים יחד באותו קונטיינר Docker אחד (מנוהלים על ידי
supervisord), כך שצריך רק שירות Render אחד - לא שלושה.

**חשוב לזכור:** לפי בדיקה שעשיתי, אפליקציית iSMART של MG ישראל מקושרת גם
מדף הדגם S9 PHEV באתר היבואן הרשמי, ויש בעלי S9 שמדווחים שהם משתמשים באפליקציה
הזו. זו אינדיקציה טובה אך לא הוכחה מוחלטת - הבדיקה הוודאית תהיה כשתריץ את
המערכת בפעם הראשונה ותראה בלוגים האם הרכב שלך מזוהה.

## מה תצטרך

1. **קו ימות המשיח קיים** - יש לך כבר. נוסיף בו שלוחה אחת חדשה מסוג "מודול API".
2. **חשבון Render** - יש לך כבר.
3. **חשבון GitHub** (חינמי) - Render בונה מתוך repository בגיטהאב. אם אין לך
   חשבון, אפשר להירשם בחינם ב-github.com, וליצור repository חדש ולהעלות אליו
   את כל קבצי התיקייה הזו פשוט בגרירה דרך האתר (אין צורך בשורת פקודה).
4. **פרטי ההתחברות לאפליקציית iSMART** (אימייל + סיסמה).
5. **קוד סודי (PIN)** שתבחר, להגנה על התפריט הטלפוני.

## שלב 1: להעלות את הפרויקט ל-GitHub

1. היכנס/י ל-github.com, צור/י repository חדש (אפשר פרטי - Private).
2. בעמוד ה-repository הריק, לחץ/י על "uploading an existing file" וגרור/י
   לשם את כל התוכן של התיקייה שקיבלת ממני (כולל התיקיות `bridge/`,
   `mosquitto/`, הקבצים `Dockerfile`, `supervisord.conf`, `render.yaml` וכו').
   **אל תעלה את קובץ `.env`** אם יצרת כזה בטעות - רק את `.env.example`.
3. Commit.

## שלב 2: יצירת השירות ב-Render

1. בדשבורד של Render: **New** -> **Web Service**.
2. חבר את חשבון ה-GitHub שלך ובחר את ה-repository שיצרת.
3. Render אמור לזהות את קובץ ה-`render.yaml` ולהציע להקים ממנו את השירות
   ("Blueprint"). אם לא - הגדר ידנית: **Language/Runtime: Docker**, ודא
   שנתיב ה-Dockerfile הוא `./Dockerfile` (שהוא ברירת המחדל).
4. **חשוב:** בחר בתוכנית **Starter** (לא Free) - השירות הזה צריך להישאר ער
   כל הזמן. תוכנית חינמית "נרדמת" אחרי 15 דקות בלי תנועה, מה שישבור גם את
   החיבור השוטף לרכב וגם את התגובה המיידית לשיחות ימות המשיח.
5. הגדר את משתני הסביבה (Environment Variables) בממשק של Render:
   - `SAIC_USER`, `SAIC_PASSWORD` - פרטי ההתחברות שלך ל-iSMART.
   - `SAIC_REGION` - נסה `eu` קודם.
   - `YEMOT_TOKEN` - מחרוזת סודית אקראית (אפשר ליצור באתר כמו
     [random.org](https://www.random.org/strings/) או פשוט להקליד משהו ארוך
     וייחודי).
   - `YEMOT_PIN` - קוד בן 4 ספרות לבחירתך.
   - `YEMOT_ALLOWED_NUMBERS` - מספרי הטלפון המורשים, מופרדים בפסיקים.
   - את `MG_ACCOUNT` ו-`MG_VEHICLE_ID` נשלים בשלב הבא, כרגע אפשר להשאיר ריק
     או למלא ערך זמני.
6. לחץ/י **Deploy**. המתן/י שהבנייה (build) תסתיים - זה עשוי לקחת כמה דקות.

## שלב 3: מציאת ה-VIN של הרכב (MG_VEHICLE_ID)

1. בדשבורד השירות ב-Render, פתח/י את **Logs**.
2. חפש/י שורות מה-`mg-gateway` שמראות התחברות מוצלחת לחשבון ה-iSMART ורשימת
   כלי רכב. אמור להופיע שם ה-VIN (מספר שילדה) של ה-S9 שלך.
3. אם ההתחברות נכשלת - זה בדיוק הרגע שבו נדע בוודאות אם S9 נתמך: שגיאת
   authentication אומרת שהפרטים שגויים, אבל אם ההתחברות מצליחה ואין רכבים
   ברשימה, זה עשוי לרמז ש-S9 לא מדווח כרכב iSMART תקין (ואז נצטרך לחקור עוד).
4. חזור/י להגדרות השירות ב-Render, עדכן/י את `MG_VEHICLE_ID` עם ה-VIN שמצאת,
   ואת `MG_ACCOUNT` עם הערך המדויק שמופיע בנושאי ה-MQTT בלוגים (בדרך כלל
   בדיוק אותו האימייל מ-`SAIC_USER`).
5. שמור/י - Render יעשה redeploy אוטומטית.

## שלב 4: הגדרת השלוחה בימות המשיח

1. היכנס/י לניהול הקו שלך בימות המשיח.
2. צור/י שלוחה חדשה (לדוגמה `2`), מסוג **"מודול API" / "תוכנית חיצונית"**.
3. הזן/י את כתובת ה-URL של השירות ב-Render (מופיעה בראש דף השירות בדשבורד,
   בפורמט `https://<שם-השירות>.onrender.com`), עם הנתיב והטוקן:
   ```
   https://השם-שקיבלת.onrender.com/yemot?token=הטוקן_שהגדרת_ב-YEMOT_TOKEN
   ```
4. שמור/י, וקשר/י את השלוחה לתפריט הראשי של הקו.

**חשוב:** התחביר המדויק של הפרוטוקול (`id_list_message`, `read`, `go_to_folder`
וכו') מבוסס על תיעוד קהילתי, כי הפורומים הרשמיים חסמו גישה אוטומטית בזמן
שהכנתי את זה. **בדוק מול "מדריך למתכנתים" הרשמי בפאנל הניהול שלך** לפני
שסומכים על זה במלואו, ואם משהו לא עובד - תקן את הפורמט ב-`bridge/yemot_bridge.py`
(פונקציות `id_list_message`, `read_digits`, `hangup`) בהתאם לתיעוד הרשמי.
לעומת זאת, **שמות נושאי ה-MQTT** (`climate/remoteClimateState/set`,
`doors/locked/set`, `location/findMyCar/set` וכו') **כן אומתו ישירות מול קוד
המקור** של פרויקט ה-gateway, ואמורים להיות מדויקים.

## שלב 5: בדיקה

1. תתקשר/י לקו, תיכנס/י לשלוחה שהגדרת.
2. תתבקש/י להקליד את הקוד הסודי (PIN).
3. לאחר מכן יושמע תפריט:
   - 1 - הדלקת מזגן
   - 2 - כיבוי מזגן
   - 3 - נעילת דלתות
   - 4 - פתיחת דלתות
   - 5 - סטטוס רכב (סוללה, דלק, נעילה, האם יש נתון מיקום)
   - 6 - צפצוף והבהוב אורות לאיתור הרכב
   - כוכבית (*) - ניתוק
4. בדוק/י ב-Logs של Render שהפקודות אכן מתפרסמות ומתקבלות (חפש/י שורות
   `Publishing ...` מה-bridge ותגובות מה-gateway).

## אבטחה - חשוב

- **הגבל/י את `YEMOT_ALLOWED_NUMBERS`** רק למספרי הטלפון שלך/המשפחה.
- **אל תוותר/י על ה-PIN**, בטח לא על פעולות נעילה/פתיחת דלתות.
- כל הערכים הרגישים (`SAIC_PASSWORD`, `YEMOT_TOKEN`, `YEMOT_PIN`) יושבים
  אצל Render כ"secret" (לא מוצגים שוב אחרי השמירה) - אל תשתפו קישור ל-URL
  המלא (כולל הטוקן) עם אף אחד.

## מגבלות ידועות (כנות!)

- לא הצלחתי לבצע כאן בנייה מלאה (`docker build`) של הקונטיינר בסביבת
  הבדיקה שלי, כי אין לה גישה לרשתות ה-registry של Docker (חסום ברמת הרשת).
  בדקתי בקפידה כל שורה מול קוד המקור האמיתי של הפרויקטים, אבל **הבנייה
  בפועל ב-Render היא המבחן האמיתי הראשון**. אם ה-build נכשל - תעתיק/י לי את
  שגיאת הבנייה מה-Logs ואני אתקן.
- תחביר הפרוטוקול של ימות המשיח (חלק 4 למעלה) לא אומת מול תיעוד רשמי.
- לא אומת סופית ש-MG S9 נתמך ב-100% - שלב 3 הוא הבדיקה הוודאית.

## קבצים בפרויקט

- `Dockerfile` - בונה את הקונטיינר המשולב (mosquitto + gateway + bridge) -
  זה מה ש-Render משתמש בו.
- `supervisord.conf` - מפעיל את שלושת התהליכים יחד בתוך הקונטיינר.
- `render.yaml` - הגדרת Blueprint אוטומטית ל-Render (אופציונלי, נוח).
- `bridge/yemot_bridge.py` - שרת ה-Flask שמתרגם בין ימות המשיח ל-MQTT.
- `mosquitto/config/mosquitto.conf` - הגדרות ה-broker הפנימי.
- `.env.example` - רשימת כל משתני הסביבה (למילוי ב-Render, לא כקובץ בפועל).
- `docker-compose.yml`, `bridge/Dockerfile` - **נתיב חלופי** אם בעתיד תעדיפו
  לעבור מ-Render לשרת VPS רגיל במקום - לא נחוצים לנתיב הנוכחי.
